# The 3 prompts from "win a hackathon in 30 seconds" 🏆

Idea → build → present. Copy each one, fill in the brackets, and go.

## 1. Idea: Gemini Deep Research

Open [Gemini](https://gemini.google.com), turn on **Deep Research**, and paste this. Put your hackathon's theme or tracks in the first line.

```
Hackathon theme / tracks: [paste them here]

You are an elite hackathon strategist with 10+ years of experience helping teams win major global hackathons.

Your task is NOT to generate generic ideas.
Your task is to uncover high-leverage, deeply niched, structurally overlooked pain points hiding inside this theme.

Generate 5 groundbreaking hackathon project ideas that judges have likely never seen before.

For each idea, follow this analytical framework:

STEP 1: START WITH A HIDDEN PAIN (GO 3 LAYERS DEEP)
1. Identify a MACRO domain (e.g., climate change, mental health, accessibility, education gaps, public health, labor markets).
2. Narrow it to a specific group of people who feel this pain every week.
3. Find the moment in their day where it hurts most, and why existing apps don't fix it.

STEP 2: PROVE IT'S REAL
Cite real data, news, reports or forum posts that show the problem exists and how many people it affects.

STEP 3: THE SOLUTION
What we build, in one sentence. The one feature that makes it different from what already exists.

STEP 4: CAN WE BUILD IT IN 24-36 HOURS?
The smallest demo that proves it works, the tech stack, and any free APIs or datasets we can use.

STEP 5: WHY JUDGES WILL REMEMBER IT
The "wow" moment in the demo, and which judging criteria it scores highest on.

End with a table ranking all 5 ideas on impact, originality and how buildable they are in one weekend.
```

## 2. Build: your vibe-coding platform

Pick one ([Replit](https://replit.com), [Lovable](https://lovable.dev), [Bolt](https://bolt.new), or whichever you like) and paste this with your idea. Run it as many times as you want until the prototype looks right.

```
Build a working web app prototype for a hackathon demo.

Idea: [one-sentence idea]
Users: [who uses it]
The one flow the demo must show: [step 1 → step 2 → step 3]

Rules:
- Make that one flow work end to end with realistic sample data. Skip login unless the demo needs it.
- Clean, modern UI that works on mobile. One primary colour.
- Show loading and empty states, so nothing looks broken on stage.
- If it needs AI or external data, put it behind one function so I can swap in a real API later.
- When you're done, list what's real and what's mocked, so I can say it honestly to the judges.
```

## 3. Present: deck in seconds

Use [Gamma](https://gamma.app) (or Canva's AI). Paste this as the prompt and you'll have a first deck in about a minute. Then edit it.

```
Create a 7-slide hackathon pitch deck for a 3-minute presentation.

Project: [name] - [one-sentence idea]
Problem: [the pain, with one real number]
Solution: [what we built]
Demo: [the one flow we'll show]
Tech: [stack]
Impact: [who benefits and how many]
Team: [names and roles]

Slides: 1 Hook (the problem in one line), 2 Problem with the number, 3 Solution, 4 Live demo, 5 How it works, 6 Impact and what's next, 7 Team and ask.
Short headlines, one idea per slide, almost no paragraphs.
```

**Tip:** open with one person's problem, not your tech stack. More on that in the [3-minute pitch kit](pitch).
